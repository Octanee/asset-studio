# API Architecture

- **Style:** REST + JSON at `/api/v1`, OpenAPI 3.1 generated by FastAPI. The frontend client is **generated** from it (`openapi-typescript`), so types cannot drift. A contract test fails CI when the spec changes without the client being regenerated.
- **Live updates:** Server-Sent Events at `/api/v1/events` (job progress, state transitions, engine status). The UI reconnects with `Last-Event-ID`.
- **Errors:** RFC 9457 problem+json with a stable `code` (e.g. `LIFECYCLE_TRANSITION_NOT_ALLOWED`, `MCP_NOT_ALLOWED`, `OVERWRITE_NOT_CONFIRMED`, `LICENCE_CONFIRMATION_REQUIRED`, `ENGINE_UNAVAILABLE`) and a localisable message key.
- **Idempotency:** POSTs that create jobs or publications accept an `Idempotency-Key` header (required for MCP).
- **Long operations:** these always return `202` with a job id; there are no blocking calls.
- **Pagination:** cursor-based for lists such as the library, the audit log and jobs.

## Confirmations as data

Every confirmation the UI shows is enforced by the API, so MCP cannot skip it:
- overwrite (RULE-004);
- licence conflict (RULE-007);
- model download (RULE-008);
- permanent delete (RULE-019);
- SDXL training estimate (RULE-016);
- enabling `mcp_can_decide`.

A request without the explicit confirmation field fails with a problem code that tells the client what to confirm. For MCP, the high-impact confirmations — overwrite, permanent delete, `mcp_can_decide` — are **refused outright** and must be done by the user in the UI.
